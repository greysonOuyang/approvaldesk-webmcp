# AWS Agents for Humans — ApprovalDesk

## Positioning

**Track:** Professional Agents

ApprovalDesk targets repetitive professional administration: reimbursement, vendor onboarding, and other structured requests where an agent can do nearly all preparation but a person must still own the consequential decision.

The central product idea matches the hackathon theme directly: **the agent runs through routine work autonomously and surfaces only when there is a real decision to make.**

## Current implementation

- Official Strands Agents TypeScript SDK: `@strands-agents/sdk`.
- A real Strands `Agent` with eight Zod-typed ApprovalDesk tools.
- Sequential tool execution over the existing exact-revision workflow authority.
- Default production model path: Amazon Bedrock through the Strands SDK.
- Deterministic offline model only for repeatable tests; the tests still execute the full `Agent.invoke()` tool loop.
- Human review UI: public GitHub Pages app.
- Browser agent integration: ten WebMCP tools over the same store.
- AgentCore-compatible Node Runtime wrapper with `/ping` and `/invocations`.
- Node 22 esbuild deployment artifact generated by `bun run build:agentcore`.

## AgentCore Runtime readiness

The current AWS documentation for direct Node deployment requires a Runtime HTTP contract with:

- `GET /ping` for health; and
- `POST /invocations` for agent requests.

ApprovalDesk implements that contract in `src/agentcore/server.ts`. Each invocation gets a fresh Strands conversation and calls the existing `createApprovalAgent`; no second approval state machine was added.

Local verification:

```bash
bun run test:agentcore
bun run build:agentcore
node dist-agentcore/app.cjs
```

The generated `dist-agentcore/app.cjs` targets Node 22 and bundles the TypeScript entrypoint, Strands agent, and Bedrock runtime path with esbuild. Strands also exposes an optional S3 context-offloader peer (`@aws-sdk/client-s3`); ApprovalDesk does not use that plugin, so the build deliberately leaves that peer external rather than adding an unused S3 dependency to the Runtime artifact.

### What is not claimed yet

No Amazon Bedrock AgentCore Runtime resource has been created yet. A real remote deployment still requires:

1. AWS account credentials configured locally;
2. IAM permissions for AgentCore/CDK-created resources;
3. an AWS target region/account selection;
4. Amazon Bedrock model access for the chosen model provider; and
5. the AgentCore CLI/CDK or an equivalent direct-code deployment API call.

Those values are account-specific and are intentionally not invented in this repository.

## Why the human boundary is durable

The important control is enforced below both agent surfaces:

- all mutating agent tools pass an exact expected revision;
- edits clear any earlier approval request/approval state;
- a human can approve only the revision currently awaiting approval;
- submission succeeds only when `status=approved` and `approvedRevision===revision`;
- stale writes fail with `REVISION_CONFLICT`;
- early submits fail with `HUMAN_APPROVAL_REQUIRED`.

That means the Strands agent can be more autonomous without acquiring human authority.

## Demonstrated agent behavior

The deterministic Strands tests prove two complete phases:

### Phase 1 — autonomous preparation

`approval_create_draft → approval_set_fields → approval_validate_draft → approval_request_human_approval`

The agent then ends its turn and surfaces the human decision.

### Phase 2 — resume after a real decision

A real `store.decide(..., 'approve')` occurs outside the agent. A later invocation then performs:

`approval_get_draft → approval_submit_approved_draft`

The agent never receives or calls a tool that grants approval.

## Demo plan (≤5 minutes)

1. **Problem (30s):** repetitive professional forms are automatable, but final commitments should remain human-owned.
2. **Autonomous run (90s):** ask the Strands agent to prepare vendor onboarding; show typed tool calls through draft creation, field entry, validation, and approval request.
3. **Decision boundary (45s):** show the agent stops; open the human queue and review exact values/risk warnings.
4. **Human approval + resume (45s):** approve the exact revision; invoke the agent again; show successful final submission.
5. **Safety proof (45s):** demonstrate stale revision or pre-approval submit failing closed; show audit trail.
6. **Architecture (30s):** one store authority, three adapters — WebMCP, Strands, and AgentCore Runtime HTTP.
